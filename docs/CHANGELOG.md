# CodeOracle Docs — Changelog

Dated log of material decisions across `intro.md`, `production-spec.md`, and `PRD.md`. Keep entries to one line; link to the section if it needs more context.

---

- **2026-08-27** — Initial product brief created (`intro.md`): product test, differentiation, phased single-repo → monorepo → multi-repo scope, MVP capability list.
- **2026-08-27** — Production spec created (`production-spec.md`): nine hardening changes over the intro (tree-sitter chunking, decision extraction pipeline, Postgres day one, pinned embeddings, MCP auth, eval harness, real incremental-reindex algorithm, multi-language chunking, license/CI).
- **2026-08-27** — Cost constraint locked to ₹0: free-tier component map added (OCI self-host, Ollama embeddings, free LLM chat chain).
- **2026-08-27** — LLM layer generalized from a fixed Gemini→Groq→OpenRouter chain into a **universal OpenAI-compatible gateway** (any `baseUrl` for chat + embeddings, config-driven, free-by-default).
- **2026-08-27** — Stage PRD created (`PRD.md`): Stage 0–7 deliverables and success gates, FR/NFR list, risks, metrics, Definition of Done as single source of truth for "is this done."
- **2026-08-27** — Doc review pass: fixed intro/spec stack disagreement (SQLite vs Postgres — Postgres wins), removed dangling "diagram above" reference in spec §2, scoped `review_comment` decision source out of MVP explicitly, added embeddings-endpoint failover requirement (FR-14/NFR-10), added secret-redaction requirement before sending text to external LLM endpoints (FR-13/NFR-9), added concrete OCI RAM budget math to Stage 0, defined fixture-repo strategy for the eval harness (checked-in `test/fixtures/sample-repo`, not an external clone), de-duplicated intro's "Success criteria" to point at PRD §9 instead of maintaining two DoD lists.
- **2026-08-27** — Docs shipped to `CodeOracle/docs/` (renamed `CodeOracle-intro.md` → `intro.md`, `CodeOracle-production-spec.md` → `production-spec.md`, `CodeOracle-PRD.md` → `PRD.md`); added this changelog and a docs index (`README.md`).
- **2026-08-27** — Competitive research pass (triggered by naming search): found 6+ existing tools in the same niche (decidex, WhyCode, DecisionNode, RetainDB, wai, whodecided). WhyCode in particular is materially more advanced than the planned MVP (AST provenance, drift detection, quality harness, benchmarks, OAuth, pricing). Created `competitive-strategy.md` with full comparison, repositioned the wedge around 4 confirmed-open gaps (hybrid code+decision retrieval, GitHub-webhook shared-team server model, universal OpenAI-compatible gateway, multi-repo workspace), and added explicit non-goals to `PRD.md` §3.2 (drift detection, AST provenance, quality harness, OAuth/billing) to avoid rebuilding what WhyCode already does well.
- **2026-08-27** — Resolved the "go narrower / infra-play" pitch option considered in `competitive-strategy.md` §7: checked "universal gateway as headline" against LiteLLM (47.8k stars, SOC-2/ISO certified)/Portkey/OpenRouter and rejected it — that framing invites comparison to a bigger, better-funded, already-solved market. Finalized pitch keeps decisions co-headline (not demoted) alongside hybrid code search, with the universal gateway kept as a supporting feature line, never the marketed identity. Added §5a to `competitive-strategy.md`; updated §5 pitch wording and §7 to mark this resolved rather than open.
- **2026-08-28** — **Major finding, user-sourced:** deep research on Graphify (`Graphify-Labs/graphify`) — 111,625 stars, YC S26-backed, created April 2026 (100k+ stars in <5 months). Re-scored the four "confirmed-open gaps" from §4: multi-repo workspace is now **closed** (Graphify has `graphify global`); hybrid code+decision MCP surface and GitHub-webhook team-server model are **weakened** (Graphify solves the same problems via graph queries + PR tools, and git-hooks + committed artifact + shared HTTP server, respectively); universal gateway w/ automatic failover remains the narrowest **still-open** point (Graphify auto-detects one backend by priority, doesn't fail over across providers on error). Added §9 (deep research), re-scored table, and §9.6 (three unresolved options: proceed narrower / study Graphify's source first / pivot to ContextVault) — explicitly left open for the owner, not resolved unilaterally, given the scale of this finding relative to the earlier six tools.
- **2026-08-28 (correction + deeper analysis, same day)** — Verified two claims by reading primary sources instead of secondary aggregators: (1) **corrected an over-broad earlier claim** — "Graphify's roadmap is heading into ContextVault's territory" conflated the company's actual funded product (Graphify Enterprise: PR-verification/merge-gate/code-review, confirmed via the official YC launch page and `graphify.com`) with **Penpax**, a separate, much earlier-stage, individually-focused, on-device "digital twin" side-waitlist with no confirmed funding or shipped product. Corrected verdict: Graphify Enterprise does not compete with ContextVault; Penpax is a distant, differently-scoped, unproven adjacent concept. (2) **Source-verified (not inferred)** that Graphify's actual extraction schema (`ARCHITECTURE.md`) has no typed Decision object — confirms the `find_decision` artifact gap is real. Also found, by reading the module list, that Graphify has **zero webhook-listener code** — corrects the earlier "weakened" scoring on the GitHub-webhook gap upward (less weakened than first stated). Added §9.5 (correction) and renumbered old §9.5/9.6 to §9.6/9.7. **Added §11**: an honest standalone strength/weakness re-analysis — verdict: weak as a head-to-head Graphify competitor, moderate-to-strong as a narrow technical component (typed decision ledger + webhook-driven freshness), with a third "complementary MCP add-on to existing graph tools, not a replacement" framing proposed but not decided.
